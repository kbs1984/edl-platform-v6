# Philosophy Canon - Immutable Principles of EDL Platform

## The North Star Statement
**"We're building the Cyworld of education, where students construct academic identity with the same passion they once decorated virtual rooms. Every feature must answer: Does this help students express who they are becoming?"**

---

## Core Philosophical Pillars

### 1. Identity Over Function 🌟
**Principle**: Features that build identity matter more than features that work perfectly.

**In Practice**:
- A buggy profile customization system > Perfect attendance tracking
- Working visitor counter > Flawless gradebook
- EmCoin transactions > Advanced reporting

**The Test**: Would a student show this to friends? If no, it's not priority.

### 2. Text is Rex 📜
**Principle**: Truth lives in transparency. Code we can read beats magic we can't understand.

**From v5**: "The terminal purists were right"
**In v6**: Every system inspectable, every decision documented

**In Practice**:
- Server Actions over hidden APIs
- SQL migrations over ORM magic
- Markdown documentation over video tutorials
- Claude Code over no-code platforms

### 3. Human Truth A Priori | Machine Truth Over Speed ⚖️
**Principle**: Humans inherently know truth; machines must prove it with evidence.

**Human Side**:
- Trust developer intuition about user needs
- Believe user feedback over metrics
- Value creative vision over data

**Machine Side**:
- Reality Agents validate every claim
- 97% consensus required for truth
- Evidence beats assumptions always
- Correctness over performance

### 4. Truth Over Timing ⏰
**Principle**: Better to be late with truth than on-time with lies.

**From Constitutional OS**: Retroactive honesty acceptable
**In Practice**:
- Log work even if session ended
- Admit failures in handoffs
- Document actual vs planned
- Fix quietly, announce loudly

### 5. Progress Over Perfection 📈
**Principle**: Ship at 95%, iterate to 100%.

**The "95% Syndrome"**: Good enough to use beats perfect but unshipped
**In Practice**:
- Activity Runtime shipped without all features
- Friends system works without real-time
- Dashboard functional before beautiful

### 6. Sessions Build on Sessions 🔗
**Principle**: Context accumulates. Every session inherits all previous wisdom.

**Implementation**:
- Session logs are constitutional
- Handoffs transfer context
- YAML queries prevent re-discovery
- Living Progress Matrix tracks everything

### 7. Evidence is Emperor 👑
**Principle**: No guesswork. No assumptions. Only verification.

**The Protocol**:
1. Query existing work first (YAML)
2. Check Reality Agents for truth
3. Read actual code/database
4. Test with real actions
5. Document what IS, not what SHOULD BE

## The Cyworld Principles (Identity Layer)

### Daily Engagement Drives Value 📅
- Students must want to check daily
- "Today" counts matter more than total counts
- Recent activity > Historical achievement
- FOMO (Fear of Missing Out) is a feature

### Social Validation Creates Worth 👥
- Features gain value when others can see them
- Public achievements > Private progress
- Friend activity > Solo accomplishment
- Visitor tracking essential

### Virtual Economy Enables Expression 💰
- EmCoins make achievement tangible
- Spending reveals priorities
- Earning creates pride
- Parents pay when they see value

### Customization IS Identity 🎨
- Every student space must be unique
- Themes/colors/layouts = self-expression
- Achievements as decorations
- Profile as personal brand

---

## Philosophical Tensions (How We Choose)

### When Speed vs Truth Conflict
**Truth wins**. Use Reality Agents, wait for consensus.

### When Function vs Identity Conflict
**Identity wins**. Build what students will show off.

### When Complex vs Simple Conflict
**Simple wins**. Text is Rex - transparency over cleverness.

### When Perfect vs Shipped Conflict
**Shipped wins**. 95% Syndrome is acceptable.

### When Innovation vs Convention Conflict
**Convention wins**. Use existing patterns from v5/Cyworld.

---

## Anti-Patterns (What We Never Do)

### Never Guess When We Can Query
- Always run YAML queries first
- Check Reality Agents before assuming
- Read the actual database/code

### Never Hide Behind Abstraction
- No black-box frameworks
- No unexplainable magic
- No "it just works" without knowing how

### Never Ship Without Identity Hook
- Every feature must help express identity
- If students won't show it off, don't build it
- Function without expression is failure

### Never Break Context Chain
- Always read previous handoffs
- Always create session logs
- Always update Progress Matrix
- Never start from zero

### Never Claim Without Evidence
- No "should be working" without testing
- No "probably deployed" without checking
- No completion claims without Reality validation
